\chapter{Introduction}
\label{section:introduction}

In modern computing workloads, it is seldom the case that a single machine is used to execute the workload. An effective system should be able to take in numerous tasks, comprehend what resources each task requires, pick an appropriate worker, execute the task reliably, and store the outcome. This is even more difficult when there is heterogeneity among workers. A single worker can have a larger CPU, another worker can have a larger memory, and the most optimal choice can change every few seconds as work is started and finished.

The project designed in this work is named as \textbf{Agentic Cloud Cluster}. It is a distributed cluster of Go-based management that schedules Docker-based jobs on worker nodes. The cluster framework and the PPO-based scheduler are the center of attention in the project. The other utilities around are considered as mere auxiliary aspects of the system.

\section{Project Definition}
\label{section:proj_def}

The project can be defined as follows:

\begin{quote}
To create a distributed task execution system in Go, and enhance task placement decisions with reinforcement learning schedule based on Proximal Policy Optimization.
\end{quote}

At its core, the system has one master node and several worker nodes. The master is responsible for receiving tasks, keeping an eye on the workers, saving the progress of each task, and asking the scheduler which worker should handle the next job. Each worker runs its assigned task inside a Docker container and then reports back to the master with the outcome. Because the scheduler sits behind a clean interface, it can be swapped or upgraded without touching the worker execution code.

\section{Motivation}

The simplest rule is the first scheduling solution most systems employ. Round-Robin is simple to conceptualize: dispatch one job to worker 1, the next to worker 2, etc. This comes in handy as a benchmark but does not take into consideration whether the worker has sufficient resources, whether it is already busy, and whether the work is bound to miss its deadline.

This can be enhanced by heuristic schedulers that include rules. An illustrative example is that a scheduler can give preference to the worker with the most available CPU or the least estimated risk. Nonetheless, it is hard to tune the fixed rules as the correct trade-off depends on the type of workload. A memory-heavy task, a burst of short tasks, and a CPU-intensive task, do not require the same decision rule.

This is what led us to explore reinforcement learning. In reinforcement learning, an agent tries different actions and learns from the feedback it gets back \cite{sutton2018reinforcement}. When this idea is applied to cluster scheduling, the state is the current snapshot of the cluster, the action is the worker that gets picked, and the reward reflects how good that placement turned out to be. This fits scheduling naturally, because every time a task is placed on a worker, the cluster state changes as a result.

\section{Project Objectives}
\label{section:proj_obj}

The project had the following objectives:

\begin{itemize}
    \item Create a working Go master-worker cluster that is capable of executing Docker-based tasks.
    \item Worker registration, heartbeat, resource tracking, task lifecycle, and result storage.
    \item Have a clean scheduling boundary, such that the various scheduling algorithms can be compared.
    \item Introduce baseline scheduling and PPO-based scheduling.
    \item Train PPO with realistic cluster traces and a reward function consistent with feasibility, queue pressure, tail pressure, and load balance.
    \item Test the system using repeatable campaigns and communicate the findings in a candid manner.
\end{itemize}

\section{Scope}

The distributed cluster and PPO scheduler is the core scope. The report deliberately avoids one-sided attention to the auxiliary interfaces or monitoring tools. They can be present in the form of supporting utilities in the repository, but the technical contribution is the Go control plane, worker execution layer, and reinforcement learning scheduler.

\section{Main Contributions}

The main contributions are:

\begin{enumerate}
    \item A Go-based distributed task execution system with master nodes and worker nodes.
    \item A scheduler interface, which allows simple baselines and PPO scheduling.
    \item A PPO service that accepts scheduling requests via gRPC and gives a worker decision.
    \item A trace replay training environment using lifecycle based resource accounting.
    \item Reward design penalizing infeasible placement, queue pressure, tail pressure, and imbalance.
    \item A benchmark environment to compare scheduling behavior to load patterns.
\end{enumerate}
