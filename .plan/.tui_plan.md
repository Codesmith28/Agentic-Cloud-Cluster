
# Dual-Mode Master UX: Preserve CLI, Add Bubble Tea TUI

## Summary

- Add an explicit runtime UI selector to the master: `--mode cli|tui`, with `CLOUDAI_UI_MODE` as env fallback and `cli` as the default.
- Keep the current readline-based CLI behavior and command syntax intact in CLI mode.
- Build a full-screen Bubble Tea TUI for TUI mode, with a persistent command bar, mini dashboard, worker panel, task/queue views, live log monitor, and activity feed.
- Target full command parity by routing both CLI and TUI through one shared command/control layer instead of maintaining two separate implementations.

## Implementation Changes

- Update [master/main.go](/Users/codesmith28/personal/Projects/acc/BTEP/master/main.go) to resolve UI mode before launching the interface, preserve `CLOUDAI_HEADLESS=true` as highest-precedence no-UI mode, and start either the existing CLI or the new Bubble Tea app.
- Update [runMaster.sh](/Users/codesmith28/personal/Projects/acc/BTEP/runMaster.sh) and startup docs so `./runMaster.sh` keeps today’s CLI behavior and `./runMaster.sh tui` launches the new TUI.
- Introduce a shared `internal/console` or `internal/controlplane` package that owns command parsing, command execution, cluster snapshot assembly, task log streaming, and structured command results for both UI modes.
- Refactor [master/internal/cli/cli.go](/Users/codesmith28/personal/Projects/acc/BTEP/master/internal/cli/cli.go) and [master/internal/cli/benchmark.go](/Users/codesmith28/personal/Projects/acc/BTEP/master/internal/cli/benchmark.go) so the CLI becomes a thin readline shell over the shared executor instead of holding the business logic directly.
- Add typed shared models such as `DashboardSnapshot`, `WorkerRow`, `TaskRow`, `QueueRow`, `MasterHostResources`, `RecentEvent`, and `CommandOutcome`; `CommandOutcome` should contain transcript text plus structured UI effects like `focus_worker`, `focus_task`, `open_monitor`, `toast`, and `refresh`.
- Add master-side live resource sampling under `internal/system` so the TUI can show both cluster-wide capacity/utilization and local master-host CPU, memory, and storage; reuse `GetClusterSnapshot()` for cluster totals and sample host resources on a short ticker.
- Build a new `internal/tui` package on `bubbletea`, `bubbles`, and `lipgloss`; the default wide layout should be top status rail, left main pane, right worker pane, and bottom command centre/transcript.
- Make the overview pane show total workers, active workers, queued tasks, running tasks, scheduler, cluster CPU/memory/storage saturation, master host resources, last update time, and a small recent-events strip.
- Make the worker pane show sortable worker rows with ID, IP, active state, load, task count, and allocated/available resources; selecting a worker should reveal its detail card and current tasks.
- Make the main pane tabbed between Overview, Workers, Tasks, Queue, Logs, and Activity; on narrow terminals, collapse the split layout into stacked tabs/drawers rather than trying to preserve the desktop layout.
- Keep the TUI command centre CLI-compatible, accepting the same existing commands and flags: `help`, `status`, `workers`, `stats`, `internal-state`, `fix-resources`, `list-tasks`, `register`, `unregister`, `task`, `dispatch`, `monitor`, `cancel`, `queue`, `benchmark`, `workload-submit`, `files`, `task-files`, `download`, and `exit/quit`.
- Treat typed commands as the source of truth for parity, and let panels add only thin shortcuts for common flows like refresh, submit task, monitor selected task, cancel selected task, unregister selected worker, and switch panes.
- Run all blocking work as async Tea commands so `monitor`, `benchmark`, `workload-submit`, downloads, registration, dispatch, and task submission stream progress into the transcript/activity area without freezing the UI.
- Implement a simple keymap: `tab` and `shift+tab` switch panes, `/` focuses the command bar, `esc` returns focus to navigation, `enter` executes, `r` refreshes, `m` opens monitor for the selected task, `c` cancels the selected task, `u` unregisters the selected worker, `q` exits the current live subview, and `ctrl+c` exits the app.
- Add subtle “alive” motion only where it communicates state: pulsing heartbeat dot on telemetry updates, animated resource bars on value changes, spinners for active commands, row flash on task status changes, and streaming log output in the monitor pane.
- Keep REST, gRPC, and the React web UI unchanged in this work; the TUI should use in-process services rather than talking back to the master over HTTP/WebSocket.

## Public Interface Changes

- Add `masterNode --mode cli|tui` and `CLOUDAI_UI_MODE=cli|tui`.
- Keep `CLOUDAI_HEADLESS=true` as the override that disables both CLI and TUI.
- Preserve the current CLI command syntax exactly, and make the TUI command bar accept the same syntax.
- Do not change worker protocols, REST endpoints, or web UI routes for this feature.

- Run the existing Go test suites unchanged, then perform a manual smoke pass in both modes: start master in CLI, start master in TUI, register worker, submit task, monitor logs, cancel task, run benchmark, submit workload, and exit cleanly.

## Assumptions

- Full parity means all existing CLI commands work from the TUI command bar; panels are convenience surfaces, not a second command system.
- The TUI runs inside the same master process, not as a separate remote client.
- One live `monitor` session at a time is acceptable because it matches the current CLI behavior; a new monitor command replaces the active stream while keeping prior transcript output.
- “Net system resources” means both cluster-wide capacity/utilization and the master host’s live CPU, memory, and storage view.
- The visual style stays minimal and terminal-native, inspired by Copilot CLI and Claude Code: text-first, low chrome, keyboard-driven, and animated only where it improves feedback.
