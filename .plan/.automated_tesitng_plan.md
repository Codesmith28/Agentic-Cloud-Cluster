# Master-Driven E2E Test Workflow

## Summary

- Make automated testing a first-class master capability instead of a manual runbook.
- Keep the current `go test ./...` suites as preflight, then add a live-cluster workflow that starts a local headless master, launches heterogeneous worker containers, runs assertions, exports artifacts, and tears down automatically.
- Put the real logic in a shared workflow engine so the same suite can be invoked from `master> test ...`, non-interactive `./masterNode test ...`, Make targets, and a Codex skill.
- Reuse the existing `testbench` workloads and observability assets where possible; do not depend on unmerged feature branches.

## Interface Changes

- Add a new master command surface: `test list`, `test run <smoke|reliability|ui-smoke|evidence|full>`, `test cleanup`.
- Add non-interactive binary mode with the same grammar: `./masterNode test run <suite> [-profile <hetero-small|recovery-lab>] [-out <dir>] [-keep-env] [-ui-smoke] [-scheduler <current|RR|RTS>]`.
- Add `MASTER_BIND_ADDR` and `MASTER_ADVERTISE_ADDR` so worker containers can reach a host-run master reliably; keep current behavior when unset.
- Add a host-master compose topology in `testbench/` that starts Mongo, Prometheus/Grafana, DinD sidecars, and worker containers only; workers publish fixed host ports and register using host-reachable addresses.
- Keep workload JSON unchanged; add separate scenario manifests that declare workload, fault injection, and assertions.
- Add a thin Codex skill that only selects a suite, runs the master `test` command, reads artifacts, and summarizes failures.

## Implementation Changes

- Create `master/internal/testworkflow` to own environment orchestration, worker registration, scenario execution, assertions, artifact capture, and cleanup; keep `master/internal/cli` as parser and renderer only.
- Refactor current `testbench` helpers so the workflow engine reuses workload files, metrics export, and report generation instead of duplicating polling logic.
- Interactive `master> test ...` runs against the already-running master and current scheduler.
- Non-interactive `./masterNode test ...` starts headless test mode and is the source of truth for agent-driven runs.
- For scheduler matrix and evidence runs, do not add a dynamic scheduler API; start fresh master instances per `SCHED_ALGO` so RR and RTS runs stay isolated and reproducible.
- Write each run to `results/testbench/<timestamp>-<suite>/` with `summary.json`, assertion results, master and worker logs, task and attempt snapshots, Prometheus exports, and UI screenshots when enabled.

## Suite Checklist

- `smoke`: start worker stack, register 3 heterogeneous workers, assert `/health`, `/api/workers`, `/telemetry`, `/ws/telemetry`, submit one deterministic task, verify status transitions, logs, attempt metadata, and one output-file round trip.
- `reliability`: exercise queue-and-drain, cancellation of a long-running task, bad-image failure, non-zero-exit failure, worker timeout or kill with requeue, stale-result suppression, and resource release after each terminal state.
- `ui-smoke`: start the UI, register and login a test user, confirm dashboard renders live workers, workers page shows the cluster, and tasks page shows a submitted task reaching terminal state.
- `evidence`: run the live heterogeneous workload against fresh RR and RTS masters, collect Prometheus and master snapshots, and emit Markdown plus JSON comparison reports.
- `full`: run `go test ./...` first, then `smoke`, `reliability`, `ui-smoke`, and `evidence` in that order, stopping on first invariant failure but preserving artifacts.

## Test Plan

- Keep existing unit and in-process scheduler tests as the fast gate; the new workflow covers what they do not: multi-process bootstrap, Docker execution, telemetry streams, HTTP contracts, recovery, file handling, and light UI behavior.
- Add deterministic verification images or commands for success-with-output, hang-and-cancel, exit-nonzero, and pull-failure so every live assertion is reproducible.
- Acceptance for “manual testing removed”: one command must bring the environment up, run the selected suite, produce a pass or fail summary plus artifacts, and tear everything down without manual worker registration, manual task submission, or manual log watching.

## Assumptions

- Source of truth is the `BTEP` branch; the workflow must run against current repo state without depending on other branches.
- Light UI smoke is in scope; full browser regression is not.
- Docker and Node are available locally; generated results are artifacts and should not be committed.
- The master `test` command is the operator UX, but the deterministic source of truth remains the shared workflow engine and its artifact bundle.
