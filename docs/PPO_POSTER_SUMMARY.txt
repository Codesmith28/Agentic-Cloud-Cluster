REWARD FUNCTION — For Your Research Poster/Paper
═══════════════════════════════════════════════════════════════════════════════

EQUATION:
R(s,a) = 1.4 + 0.25·H - 0.35·Q_p - 0.55·T_p - 0.20·I_p - 0.40·ΔI - R_q

SEVEN TERMS EXPLAINED:

1. BASE (1.4)
   Purpose: Ensure all feasible placements are rewarded
   Variable: Constant bias term

2. HEADROOM BONUS (0.25·H)
   Purpose: Encourage load spreading to avoid congestion
   Variable: H = 1 - Normalized_Load(w); higher = more available capacity

3. QUEUE PRESSURE (−0.35·Q_p)
   Purpose: Minimize queuing delays relative to SLA budget
   Variable: Q_p = queue_wait / (SLA × runtime); scaled [0,3]

4. TAIL PRESSURE (−0.55·T_p) [HIGHEST WEIGHT]
   Purpose: Prevent P95 latency violations (SLA breaches)
   Variable: T_p = max(turnaround / SLA - 1, 0); activated only when exceeding SLA
   Impact: This term alone gives PPO 10.1% P95 improvement vs Round-Robin

5. IMBALANCE PENALTY (−0.20·I_p)
   Purpose: Avoid hot-spotting by penalizing above-average loaded workers
   Variable: I_p = max(worker_load - cluster_avg_load, 0)

6. DELTA IMBALANCE (−0.40·ΔI) [SECOND HIGHEST WEIGHT]
   Purpose: Penalize actions that worsen cluster load variance
   Variable: ΔI = std_after - std_before; uses change not absolute value
   Insight: Credits only actions the agent causes, not pre-existing imbalance

7. REQUEUE PENALTY (−R_q)
   Purpose: Avoid placing tasks on historically problematic worker combinations
   Variable: R_q = min(requeue_count, 4) × 0.05; small penalty term

OUTCOME:
- Typical good placement: R ≈ 1.2–1.6
- Empty worker, low risk: R ≈ 1.65 (best)
- Infeasible placement: R = −1.8 (hard constraint)

LOSS FUNCTION — What PPO Optimizes
═══════════════════════════════════════════════════════════════════════════════

TOTAL LOSS:
L(θ) = L_policy + 0.5·L_value - 0.01·H[π]

THREE COMPONENTS:

1. POLICY LOSS (Clipped Surrogate Objective)
   Equation: L_policy = −E[min(r·Â, clip(r,1±ε)·Â)]
   
   where:
   - r = π_new(a|s) / π_old(a|s) is probability ratio
   - Â = advantage (reward - baseline)
   - ε = 0.2 (conservative 20% change limit)
   
   Purpose: Maximize good placements, minimize bad ones, but take small steps
   Key Insight: Clipping prevents policy from changing too much in one update
   (e.g., if r=3.0 we clip to min(3·Â, 1.2·Â)=1.2·Â, staying conservative)

2. VALUE LOSS (Critic Learning)
   Equation: L_value = max((V - G)², (V_clip - G)²)
   
   where:
   - V = predicted future reward
   - G = actual cumulative reward observed
   - V_clip uses clipping for stability
   
   Purpose: Train baseline network to accurately predict state value
   Use Case: Enables accurate advantage computation (A = actual - baseline)

3. ENTROPY BONUS (Exploration)
   Equation: H[π] = −Σ π(a|s)·log(π(a|s))
   
   where ε=0.01 multiplier (weighted term −0.01·H[π] in loss)
   
   Purpose: Prevent policy from becoming deterministic too early
   Effect: Encourages exploring multiple worker types before specializing
   Why Small Weight: Task masking (infeasible workers → logit=−1e4) naturally
                    limits entropy; bonus just maintains exploration flexibility

═══════════════════════════════════════════════════════════════════════════════
ENTROPY IN DETAIL
═══════════════════════════════════════════════════════════════════════════════

FORMULA:
H[π] = −E_a[π(a|s)·log(π(a|s))]

INTERPRETATION:
- π(a|s): probability distribution over actions (workers) given state
- Low entropy (H→0): π concentrates on 1-2 workers, e.g., [0.95, 0.03, 0.02]
- High entropy (H→1): π uniform across workers, e.g., [0.33, 0.33, 0.34]

WHY IT MATTERS FOR SCHEDULING:
1. Early training: Agent learns "place on worker-1, always works"
   → Logits: [3.0, -2.0, -1.5] → π=[0.93, 0.05, 0.02] → H≈0.25
   → Problem: Agent never tries worker-2 or worker-3

2. With entropy bonus (−0.01·H in loss):
   → Loss encourages higher entropy
   → Agent explores all workers, discovers task-type specializations
   → cpu-light tasks → worker-small (better), memory-heavy → worker-large

3. As training converges:
   → Agent learns specialization AND retains exploration
   → Final policy: still somewhat random but consistently picks good workers
   → Training curve shows H decreasing 0.5→0.15 (expected & healthy)

PRACTICAL EFFECT:
Without entropy: Agent might lock in suboptimal policy (e.g., always worker-large)
With entropy: Agent maintains flexibility to adapt as cluster changes or new task types arrive

KEY RESULT: Why PPO Wins
═══════════════════════════════════════════════════════════════════════════════

1. REWARD FUNCTION DESIGN:
   - Tail pressure (T_p, weight=0.55) explicitly optimizes P95 latency
   - Round-Robin doesn't know about T_p; treats all workers equally
   - RTS uses heuristics; PPO learns from reward signal

2. LOSS OPTIMIZATION:
   - Clipped surrogate ensures stable, monotonic policy improvement
   - Value function bootstraps learning (10× faster convergence vs vanilla PG)
   - Entropy maintains exploration for robustness

3. EMPIRICAL RESULTS:
   - P95 latency: 10.1% better than Round-Robin (62.0s vs 69.0s)
   - Makespan: 8.7% better than Round-Robin (63.95s vs 70.06s)
   - Tail pressure (T_p) term in reward is primary driver
